# Phase 3: Resilient Offline Buffering & Idempotent Ingestion

## Objective and dependencies

Complete the capability under the eight-hour prototype scope. Phase 1 identity/storage and phase 2 validated byte serialization; input and UI work stay parallel.

Read PROJECT.md, ARCHITECTURE.md, CONTRACTS.md, TEAM_EXECUTION.md, GIT_WORKFLOW.md and VALIDATION.md. Phase numbers are traceability groups, not a serial build queue. See individual MEMBER guides for each person's entire cross-phase workload.

## Files and ownership

backend/collector/buffer_queue.py, drainer.py, transport.py; backend/saas/storage.py, ingest.py; tests/core/**; tests/scenarios/** (M3). Ownership exceptions in TEAM_EXECUTION.md apply. M1 alone edits shared contracts, core security and entry-point wiring.

## Tasks

### 1. Persistent outbox before send — M1

Every approved record commits to local SQLite before transport. WAL/FULL, one writer, stable UUID/body, restart recovery, attempts/status and bounded backpressure. Invalid/conflict records stay visible in quarantine; no silent discard.

### 2. ACK and retry — M1

One event/request for MVP; per-ID receipt after server commit, then mark delivered. Backoff capped at 8s with jitter; independent live heartbeat. Same ID/body on lost-ACK retry. Do not use HEAD reachability as a guarantee a later POST succeeds.

### 3. Transactional dedup and side effects — M1

Unique tenant/UUID; duplicate matching digest returns duplicate receipt. Mismatching body is 409. Store metadata and uniquely keyed analytic effects transactionally; cache mutates only after commit, rebuild on restart. Do not depend on TTL/in-memory dedup alone.

### 4. Late-event policy — M1

Order historical queries by event UTC time; never overwrite latest source state with older arrival. Store late events as historical without re-running live analysis; expose analysis_status. This does not claim retroactive baseline correction.

### 5. Failure tests and reconciliation — M3

Generate outage while inputs continue, lost ACK, client/server restart, reordered/duplicate data, simultaneous same-ID requests and same-ID/different-body conflict. Compare expected durable IDs with received sets, multiplicities and analytic effects. Exercise small queue cap.

### 6. Reliability indicators — M2

Render live queue/replay/receipt counters from API and scenario result. Empty queue alone does not prove delivery.

## Acceptance gate
