Complete the capability under the eight-hour prototype scope. Phase 5 incident API, phase 1 roles/commands and M3 demo source. M2 builds pending/action UI early.

## Files and ownership

backend/saas/remediation/**; backend/collector/command_runner.py (M1); backend/collector/demo_source.py (M3); frontend action controls (M2). Ownership exceptions in TEAM_EXECUTION.md apply. M1 alone edits shared contracts, core security and entry-point wiring.

## Tasks

### 1. Pure simulation helper — M3

Memory demand/capacity produces memory_pct. Implement snapshot/restore/apply_scale(1.5); do not persist/authorize commands yourself or invoke shell. M1 wraps helper with atomic persisted state/snapshot/receipt.

### 2. Single policy — M1

Allow only SCALE_CONTAINER_MEMORY with factor=1.5 on known demo source with active memory incident and matching tenant/operator. Reject real/organizer targets, arbitrary actions/parameters and unknown sources. One active action per target; three new actions/hour, rollback excluded. Revalidate at approval and execution.

### 3. Approval and command lifecycle — M1

Persist proposal, authenticated operator approval, policy result and command ID. Collector polls outbound every 2s; ensure tenant/collector scope and idempotency. Persist snapshot + new demo state + command receipt atomically; send safe result. Approval is pending until collector result, and recovery requires subsequent ordinary telemetry.

### 4. Rollback and audit — M1

Rollback successful action only; restore original capacity from saved snapshot exactly once, then emit telemetry. Append actor/time/policy/state transition/reason audit rows. Ordinary database audit is not immutable against administrators. Offline collector leaves command pending and visible.

### 5. Accurate controls — M2

Display SIMULATION, proposal/policy, approve, pending/success/failure and rollback state. Never mutate health locally or treat HTTP approve ACK as execution success.

### 6. Behavior checks — M3

Unapproved, wrong role/tenant/target, duplicate clicks, restart/ACK loss, action-rate limit, rollback after limit, and pre/post source telemetry. For memory-capacity demo require observed reduction and restoration; do not claim a real restart has an inverse.
