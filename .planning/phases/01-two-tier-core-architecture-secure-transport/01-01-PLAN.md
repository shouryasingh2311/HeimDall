# Phase 1: Two-Tier Core Architecture & Secure Transport

## Objective and dependencies

Complete the capability under the eight-hour prototype scope. No phase prerequisite; freeze contracts at G0. Other members start scaffold/adapters in parallel.

Read PROJECT.md, ARCHITECTURE.md, CONTRACTS.md, TEAM_EXECUTION.md, GIT_WORKFLOW.md and VALIDATION.md. Phase numbers are traceability groups, not a serial build queue. See individual MEMBER guides for each person's entire cross-phase workload.

## Files and ownership

backend/shared/**; backend/saas/main.py, auth.py, storage.py; backend/collector/daemon.py, transport.py; pyproject.toml; backend lockfile; scripts/security/**. Ownership exceptions in TEAM_EXECUTION.md apply. M1 alone edits shared contracts, core security and entry-point wiring.

## Tasks

### 1. Bootstrap and freeze — M1

Create backend package/manifest/working locked dependencies, ignore rules and environment example. Define strict shared models from CONTRACTS.md, source membership, role/token-to-tenant/region binding and database schema. Publish safe API examples for M2/M3.

### 2. Secure runtime — M1

Run separate collector and SaaS processes; provision local CA/server SAN certificate and client/browser trust. Implement verified HTTPX, credential validation, assigned region checks, tenant-scoped read APIs and public minimal healthz. No verify=False, payload signing or mTLS claims.

### 3. Start frontend immediately — M2

Scaffold React/TypeScript/Vite and lockfile; one typed client, metadata fixtures with MOCK banner and visible connection failures. Never wait for phase 7 to begin UI.

### 4. Start input work immediately — M3

Inventory organizer format and sample; implement JSONL RawEvent adapter, labelled development source skeleton and clean-start checklist. Feed through lead-owned collector.

### 5. Integrate first vertical slice — M1

Receive one sanitized record with matching tenant/source; persist it, return receipt and show real read API data in UI. Authentication applies to every later route; scope fixtures cover two tenants.

## Acceptance gate

V00, V01, V02; G1 also requires V03 happy path and one live rendered record.

A class import, file presence, fixture output or a mock screen is not completion. Attach observed results/commit SHA in the member status and STATE.md. Do not mark complete while referenced checks are failed or blocked. Changes to contracts require lead review and dependent tests.
