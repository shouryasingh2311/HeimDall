## Tasks

### 1. Metrics and heartbeat — M1

Wire all fixed metrics, units, null handling and separately fresh 10s heartbeat. Show resource/config fields. Heartbeat auth, timestamp and duplicate validation separate from replayed telemetry.

### 2. Complete health rules — M1

Severity is maximum across available configured signals and freshness. Excellent is default only with complete fresh expected data. CPU/memory: >=70 Good, >=85 Fair, >=95 Poor; disk_used >=75 Good, >=90 Fair, >=98 Poor; latency >=50 Good, >=120 Fair, >=500 Poor; packet loss >0 Good, >=2 Fair, >=10 Poor. service_available=false/connectivity=false or risk_score>=90 => Poor; risk_score>=50 => Fair. Missing expected signal/config invalid => at least Fair. Thresholds in config; bytes/rates are charted, not arbitrarily thresholded.

### 3. Freshness and transitions — M1

Source age>=30s => at least Fair; >=55s => Poor. Collector no fresh heartbeat>=55s => Poor; watchdog every 1s leaves deadline margin. Use max severity so stale never improves Poor to Fair. Valid heartbeat cannot refresh old source data. Timestamp/reason every actual transition; expose current and historical state.

### 4. Measure actual rendering — M2

Record first visible render per payload/session/run after UI commit/frame scheduling; POST render receipt. Clear timer/cache on tenant switch. Display sample count, cohort and clock uncertainty. Fetch or ingestion latency is not render latency.

### 5. Benchmark protocol — M1 and M3

Server records original event, receive and alert-create times; M3 records injection/offline start and status change. Calculate nearest-rank p95 over first-render samples in rolling 5min/run window. Report live and replay/outage cohorts separately plus all-event summary; no silent exclusions. Warm-up and missing samples explicit.
